# 整体功能实现分析

## 1. 系统分工

上位机运行 Python 图像处理和触屏界面。主运动控制器接受 Grbl 文本协议，驱动 XYZ；辅助微控制器接受自定义行协议，控制 R 轴、吸附电磁铁和辅助输出。SPI 屏幕是操作界面，不负责拼图求解；写字机二次开发为机械平台提供独立控制能力。

这里的 XYZ 与 R 分属两个控制器。辅助固件虽然保留五电机、四逻辑轴能力，但本系统不能据此假定 XYZ 也接到该固件。

## 2. 图像如何变成拼图方案

核心实现在 `E题开源/完赛/puzzle_vision_poker/main.py`。

1. `open_camera` 打开相机，检查可读图像及配置尺寸。
2. 四个纸面角点得到透视矩阵，`warp_paper` 将图像变为毫米尺度已知的 A4 平面。
3. 根据模式进行白色碎片或背景差异分割，清理掩膜并提取轮廓。
4. `detect_pieces` 生成中心、面积、轮廓与拾取点；拾取点尽量位于片内并远离边缘。
5. `generic_solver.py` 搜索边与边的几何组合，评估目标矩形、覆盖、重叠、间隙等约束。
6. 三片模式可由 `edge_matcher.py` 检查拼缝两侧花纹。NCC 相似度是证据之一，不能独立证明拼图正确。
7. `orthogonal_path_planner.py` 生成基础搬运路径，执行层还存在同时 XY 和路径简化选项。几何规划的正交路径与实机最终走法需要分别核对。
8. 输出结构化方案与实拍碎片合成预览，连续帧检查位置、面积、形状与目标姿态是否一致。

普通四片模式由 `spi_control/ordinary_camera.py` 加载相邻的三片项目作为维护中的几何引擎，叠加普通模式的分割和几何配置，关闭花纹门禁并设置四片数量。普通目录保留的旧入口和仿真是历史兼容代码。

## 3. 方案确认与执行

`approved_plan.py` 将方案、配置、图像与相关代码摘要绑定。界面确认的是具体方案，执行前检查编号和摘要，再复拍核对源碎片是否移动。新连接还需要操作者确认本次机械基准。

`dual_serial_executor.py` 负责两路串口握手、有效配置检查、位置转换、移动与输出控制。一般动作包括安全高度移动、到拾取点、下降、吸取、抬起、旋转、搬运、放置、释放和返回。每一步都依赖状态应答和超时处理，不等同于发送后固定等待即可认为到位。

停止时分别核对控制器停止和输出关闭；控制器重启、串口错误或停止不能确认时，需要明确报告。自动重发上一条运动可能导致重复动作，因此异常后不能假定原方案仍有效。

相机坐标为 A4 左上原点，X 向右、Y 向下；实机 Z 与 R 的符号通过配置定义。`xy_transform`、工具偏移和 Z 高度属于具体机械标定，不是可直接移植的通用常量。

## 4. SPI 显示与触摸

外部驱动 `lt758x` 分成 SPI 传输、面板时序与背光、绘图、文字和触摸五部分。显示通过 SPI 写入控制器显存，触摸通过 I2C 读取；上层用像素坐标绘制按钮、图像和状态文字。

本仓库的 `layout.py` 与 `ui_layout.json` 定义页面布局，`start_page.py` 管理交互和子进程，`camera_job.py` 生成预览，`manual_control.py` 和 `manual_page.py` 提供手动点动与输出操作。驱动使用 `SPI_DRIVER_DIR` 定位，公开版不依赖开发者的本地磁盘路径。

## 5. 写字机二次开发

`plotter/grbl_writer.py` 是独立 Python 控制端，不需要原厂桌面程序。串口命令采用逐行发送、等待 `ok` / `error` 的状态机；状态查询和暂停等实时命令使用单字节。

SVG 解析支持直线、折线、多边形及由 M/L/H/V/Z 构成的路径，转换为抬笔、移动、落笔和绘制指令。它不是完整的 SVG 排版或字体引擎，也不支持将所有曲线自动转换成可绘制轨迹。

`machine` 可读取用户提供的 JSON 机器参数。公开版配置目录改为 `.plotter`，环境变量改为 `PLOTTER_SETTINGS_DIR`；没有附带字体库、原厂程序、授权数据或解密工具。

## 6. 辅助固件

`firmware/Drive/Source/a4988.c` 利用定时器产生 STEP 脉冲，GPIO 设置方向和公共使能；`motion_protocol.c` 处理运动指令、状态与通信租约；`relay.c`、`servo.c`、`aux_control.c` 负责吸附与辅助输出。

固件上电为运动输出未使能状态，和上位机物理仿真是不同概念。实动、回零记录、辅助输出租约必须分别满足。R 的默认设定是 200 整步、16 细分、直接传动，即 3200 脉冲一圈。实际硬件必须与宏定义一致。

## 7. 本次发布采用的版本

界面使用较新的 `remote_spi/spi_control` 回传快照，核心视觉与执行器使用 `remote_project2/puzzle_vision_poker`，普通模式配置选用最后一批普通模式复核候选快照。不能仅根据目录叫“完赛”就判定它比回传版更新。

这些是现有本地快照的整理，并非从已经损坏的开发板重新导出。`source-manifest.json` 记录复制来源和原文件摘要；公开版另外做了路径移植、去品牌文案和配置清理，原文件摘要不等于公开版最终文件摘要。

## 8. 完成程度

识别、规划、界面、双串口执行和最终复拍的代码链路已具备。视觉偶发不稳定和机械重复精度仍限制整机效果；开发板损坏使后续优化中断。完整缺陷与复现边界见 `KNOWN_ISSUES.md`。
