# 已知缺陷与维护状态

## 视觉优化中断

原开发板已损坏，后续视觉优化和实机复测无法继续进行。视觉在部分场景下仍不稳定。项目已有两段由作者确认的 [成功运行视频](FIELD_DEMOS.md)，说明装置实现过三片扑克牌和四片普通拼图的运行流程。本次补充的是历史现场视频，没有重新进行实机测试；成功轮次也不代表偶发问题已经解决。

## 当前主要问题

| 问题 | 表现与影响 | 后续方向 |
| --- | --- | --- |
| 分割不稳定 | 光照、阴影、背景色和碎片距离变化会改变轮廓；靠近或接触的碎片可能被识别为一块 | 固定照明与曝光，优化接触轮廓拆分和边界判定 |
| 复拍误判 | 多片连成大轮廓后，模板匹配可能给出不可信的缩放、位置与角度；未匹配编号不等于确认漏放 | 限制不合理缩放，区分无法判定和确认超差，改善多片匹配 |
| 视觉结果抖动 | 连续帧稳定检查可阻止部分偶发结果，但不能证明视觉长期稳定 | 增加不同光照、材质、摆放方式的数据和重复试验 |
| 花纹歧义 | 弱纹理、重复图案或拼缝取样误差会影响三片方案排序 | 联合几何约束与纹理证据，保留人工预览核对 |
| 实际放置偏差 | 历史现场既有误判，也存在真实位移和转角偏差；不能全部归咎于视觉 | 复核工具偏移、吸附中心、旋转中心、失步和释放拖动 |
| 串口与供电 | 历史现场出现过 USB 断连、控制器重启和状态丢失 | 检查独立供电、接地、线缆与干扰；软件检测不能修复物理链路 |
| 搜索耗时 | 几何组合复杂时可能超时或无法找到方案 | 使用可重复数据分析剪枝与搜索预算 |
| 历史入口差异 | 普通拼图旧 `run_real.py` 与当前触屏共用几何引擎的路径不同 | 实机使用文档指定的触屏入口，后续统一旧入口 |
| 仿真素材缺失 | 保留仿真代码，未发布历史照片、牌面纹理与场景资产 | 自行制作无品牌、可分发的仿真素材 |
| 固件构建不完整 | 仓库提供自定义应用层，未附第三方 SDK、启动文件和厂商模板 | 在匹配的 SDK 工程中集成并验证中断和时钟 |

此前整理的日志没有给出连续整机验收通过的结论；现在补充的成功视频证明存在成功演示轮次。这两种证据的范围不同，不能将日志未连续通过写成“从未成功”，也不能将演示成功写成“已经长期稳定”。开发板损坏后没有新增实机复测结论。

## 三种不同的通过条件

1. 软件测试通过：只说明被覆盖的算法、状态机和模拟协议满足断言。
2. 空载流程通过：需要实际机构完成整条路径且无撞限、卡住、失步。
3. 拼图实物验收通过：还需要稳定吸取、旋转和释放，复拍及现场检查均满足要求，并重复完成。

本项目不能用第一项替代后两项。
